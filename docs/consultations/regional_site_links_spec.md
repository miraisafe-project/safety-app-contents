# 地域別相談先案内データ仕様・調査結果

確認日: 2026-11-29

## 今回の公開範囲

47都道府県の一次調査を行い、17都府県の19ページを掲載する。30道県の30候補は保留した。**47都道府県すべてに掲載データがそろった状態ではない。** 各自治体の全ページ・全分野を網羅した調査ではない。

県等の総合案内・若者向け案内を優先した。山梨県は教育・子育てと医療・福祉、兵庫県は総合相談とこころの専門案内を分け、同じ窓口一覧を重複して並べるだけの追加は避けた。

個別ページの事前問い合わせ、事前許諾、掲載後の連絡・報告を求める候補は、今回の「連絡不要」という条件に合わないため掲載しない。「リンクフリー」という語だけで判断していない。自治体や団体への連絡・許可申請は行っていない。

- 配信: [regional_site_links.json](../../data/consultations/regional_site_links.json)
- 調査台帳: [regional_site_links_research.json](regional_site_links_research.json)
- 公開URL: https://miraisafe-project.com/data/consultations/regional_site_links.json
- 既存の `consultations.json`、`official_site_links.json`、Flutterコード、公式サイトの表示は変更しない。
- 今回のデータを置くだけでは、現在のアプリに地域選択機能は追加されない。

## JSONの形式

UTF-8、BOMなし。ルートはオブジェクトとし、一覧のない都道府県を空の仮記事等で埋めない。

| フィールド | 型 | 必須 | 意味 |
| --- | --- | --- | --- |
| version | integer | 必須 | データ形式のバージョン。現在は1 |
| updatedAt | string | 必須 | JSONの最終更新日。YYYY-MM-DD |
| regionalSiteLinks | array of object | 必須 | 掲載条件を満たした案内ページのみの配列 |

### 各案内ページ

| フィールド | 型 | 必須 | 意味 |
| --- | --- | --- | --- |
| id | string | 必須 | 全件で一意な固定ID。英小文字で始まる英数字・アンダースコア。URL変更・並び替えでも変えない |
| prefectureCode | string | 必須 | 都道府県部分の2桁コード。01〜47。数値にしない |
| name | string | 必須 | カード等で使う案内ページ名。地域・分野が分かる名称 |
| url | string | 必須 | 対象の案内ページのHTTPS URL。認証情報を含めない |
| provider | string | 必須 | 運営元。カード等でも明示して、県等のサイトへのリンクと分かるようにする |
| description | string | 必須 | アプリ独自の簡潔な紹介文。相談対応を保証する説明ではない |
| categoryIds | array of string | 必須 | 既存の相談カテゴリID。重複なし、1件以上 |
| categoryNames | array of string | 必須 | categoryIdsと同じ順・件数の既存カテゴリ名 |
| keywords | array of string | 必須 | 内容に対応する検索語。空文字・重複・1文字語を避ける |
| displayOrder | integer | 必須 | 都道府県内での表示順。小さい順。総合・本人向けを先にし、専門案内を後にする |
| termsUrl | string | 必須 | 当該ページに適用されるリンク条件を確認したHTTPS URL |
| verifiedAt | string | 必須 | 本文・案内目的・対象者・リンク条件を確認した日。YYYY-MM-DD |
| targetUsers | string | 必須 | 本人・保護者・支援者などの区別と対象条件の補足。表示用であり、機械的な利用資格判定には使わない |

v1で必須でない任意項目は設けていない。将来の互換な項目追加に備え、読み手は未知の項目を無視できるようにする。意味や必須条件を破壊的に変更する場合は形式バージョンとアプリ対応を一緒に更新する。

`targetUsers` は、子ども本人向けと保護者向けの案内を混同しないために追加した。対象年齢・居住地・予約条件を機械判定するフィールドや個別窓口の電話・受付時間は作らない。紹介先には複数窓口があり、それぞれ条件が違うためである。

`prefectureCode` は案内する地域であり、そのページ内の全窓口が県内の全員に利用できる保証ではない。市町村単位の選択機能は作らないが、リンク先に市町村別の案内があることは妨げない。

ファイル内は `prefectureCode`、`displayOrder`、`id` の昇順で保存する。表示順は現在100、200を使用しており、連番や全県共通順位ではない。

都道府県コードと名称は、[e-Statの標準地域コード](https://www.e-stat.go.jp/municipalities/cities/areacode)の01北海道から47沖縄県までの対応と照合した。全国地方公共団体コードに対応する都道府県部分を文字列として持ち、市町村コードやチェック数字を含めない。

## 更新・キャッシュ

`version` は記事更新回数ではなく形式バージョン。現行の全国案内モデルは `version != 1` を拒否するため、内容更新だけで2へ増やす運用にしない。

現行の `OfficialSiteLinksService` / `CachedJsonResource` は24時間の再確認間隔、HTTPのETag・Last-Modified等、失敗時の既存キャッシュ継続を備える。地域別でもこの仕組みを共用するのが適している。

- 配信URL、JSONキャッシュ、最終確認時刻、失敗時刻、HTTP検証子のキーは全国向けと分離する。
- 新しい形式として `regionalSiteLinks` を読み、`prefectureCode` と `targetUsers` を保持する。既存モデルをそのまま使うだけでは地域情報が失われる。
- 有効なJSON全体を検証してからキャッシュを置き換える。不正形式・ネットワーク障害時に既存の有効なキャッシュを消さない。
- `updatedAt` は日単位のため、同日に複数回変更される可能性がある。同じversion・日付でも内容が更新され得る。取得済み本文を日付の等しさだけで破棄しない。
- Web版は既存実装のようにCORSで利用可能なHEADのLast-Modified・Content-Lengthを使い、ETagのブラウザ露出を前提にしない。
- ユーザーが選んだ都道府県や悩みの検索語は外部JSON取得URLへ送らない。位置情報を取得する必要はない。
- データの取得先はアプリ内の固定HTTPS URLとし、カタログのリンク先を順に自動取得する設計にはしない。

## 検索・表示

現行アプリの `lib/utils/consultation_search.dart` と `lib/data/consultations/official_site_link_models.dart` を確認した。

正規化は全角ASCII→半角、半角カナの補正、カタカナ→ひらがな、英小文字化、空白・長音記号の除去。漢字→読み仮名変換やハイフン除去はしない。そのため、虐待/ぎゃくたい、不登校/ふとうこう、発達障害/はったつしょうがい等は別に登録する。

全国案内の関連判定はカテゴリID一致、カテゴリ名の正規化後一致、検索語内の登録キーワード一致のいずれかで成立する。`query.contains(keyword)` 方向であり逆ではない。1文字語は除外し、英数字のみの語は境界条件がある。カテゴリと検索語を両方渡すとANDではなくORである点に注意する。

1. 最初に都道府県コードで絞り込む。
2. 絞り込み後に既存の関連判定を適用する。全国分に対して先に判定すると、他県の同じカテゴリのページが混ざる。
3. 都道府県内でdisplayOrder順に表示する。同順位の場合の安定順としてidを使う。
4. 全国向け案内は別区分で併用し、既存IDを参照する。全国サイトが選択県だけに自動で絞られたように表示しない。
5. IDと正規化したURLで重複を排除する。名前の一致だけで同じページと判断しない。
6. 県内データが0件でも「相談先がない」という意味にしない。既存の全国案内へ進める状態にする。
7. targetUsersを参照し、保護者専用窓口を本人向けと断定しない。受付中・24時間などの判定も行わない。
8. リンク先の運営元が分かる状態で、外部ブラウザ等の独立した表示で開く。フレーム埋め込み、ロゴ転載、提携・認定を示唆する表示をしない。
9. 命や安全の深刻な悩みでは、既存の全国向けこころ・SOS案内も併用する。地域別データだけを唯一の導線にしない。
10. 地域別リンクをブックマークする場合は、既存窓口IDとの名前空間を分ける。掲載取り下げ時に古いキャッシュを無期限に再掲載しない。

現行アプリは今回の新URLを読まない。都道府県選択、地域別モデル・サービス、既存全国案内との組み合わせ、空状態、更新・エラー・ブックマーク等の実装とUIテストが別途必要。

## 調査台帳の管理

台帳のversionは台帳形式のバージョン。prefecturesは01〜47を各1件持ち、candidatesに掲載・保留の双方を記録する。候補のstatusはpublishedまたはheld、公開IDはpublishedの場合のみ持つ。

`contactRequirement` はnone、inquiry_required、permission_required、notification_required、unclear。掲載はnoneに限る。これは今回の掲載選定の記録であり、法的な許諾保証ではない。規約の変更や個別の取り下げ依頼があれば再確認する。

`contentEvidence` は確認した内容の独自要約、`decisionBasis` はリンク条件の判断根拠、`termsScope` は適用範囲。`checkedAt` は確認作業日で、取得できなかった候補では確認完了を意味しない。`contentVerified` と `httpStatus` を併せて見る。

`coveredTopics` と `topicCoverage` は公開候補のみを集計する。`topics` は調査上の分野名であり、アプリの新カテゴリではない。`notConfirmedTopics` は公開候補で確認できていない分野。0件の県も47件の台帳から消さない。

初回以降も同じ台帳を更新し、別の一覧を増やさない。再確認では本文・対象者・最新リンク先と、候補に実際に適用される規約の両方を見る。HTTP 200だけでverifiedAtを更新しない。ページが移動した場合は案内内容と規約を再確認して、公開IDは維持する。

## 検証方法

リポジトリルートで実行:

```powershell
node tools/validate-regional-site-links.mjs
```

JSON構文、必須項目・型、形式バージョン、日付、全47コードと名称、ID/URL/地域内順位の重複、既存カテゴリ、全国向けとの重複、掲載・保留台帳との対応・集計を検証する。規約やページの意味を自動判定するものではない。

公開前には実ページ本文と規約の読み合わせ、Git差分・対象ファイル限定の確認を行う。Pagesビルドはdataディレクトリを加工せずコピーする構成で、既存workflowやサイトデザインの変更は不要。
