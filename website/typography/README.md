# 日本語の改行処理

公式サイト専用。アプリ向け `data/` の本文やJSONは解析・書き換えません。

## 通常の追加・編集

元のHTMLや `website/news/website_news.json` に通常どおり文章を書きます。公開ビルドが本文・説明文・見出しにBudouX 0.10.4の改行候補を付けます。生成結果は `_site/` に出力し、元の文章は書き換えません。候補は文字を持たない `<wbr data-jp-auto>` です。不可視の区切り文字は挿入しません。

- 本文・説明文：BudouXの候補＋`pretty`。見出し・キャッチコピー：`balance`も維持。
- 禁則処理は`strict`、収まらない語句は`overflow-wrap: anywhere`で緊急折り返し。
- 処理済み範囲だけ`keep-all`を使い、候補のない位置での通常の文字単位の分割を抑制。ページ全体には指定しません。
- MENU、ボタン、短いラベル、日付、URL・メールを含む段落、コード、ruby、強制改行を含む段落、画像の出典欄は対象外です。対象外は従来のCSS表示を維持します。
- HTML構造やリンク要素を置換せず、テキストノードを分割して候補だけ挿入します。再処理時は自動候補だけを除去して再生成します。
- 動的なお知らせは同じ候補生成関数を使います。今後追加される動的本文もMutationObserverで検出します。`website:content`イベントによる明示的な通知も使用できます。

## 意味のまとまりと優先候補

```html
<p>…ことなど、<wbr data-wrap-priority><span data-wrap-group>幅広いテーマを扱います。</span></p>
```

`data-wrap-group`は、表示領域に収まるときだけまとめる短い表現に使用します。収まらない場合は内部のBudouX候補による折り返しを許可します。長い段落全体を指定しないでください。

`<wbr data-wrap-priority>`は強制改行ではありません。評価処理の対象内で優先候補となり、1行に収まる場合は改行しません。指定のない通常の`wbr`は通常候補として扱います。

お知らせJSONのプレーンテキスト段落では、任意で次の指定も使えます（HTMLは渡しません）。各文字列の最初の一致を使用し、重なるグループは無視します。

```json
{"type":"paragraph","text":"今知っておきたいことを、必要とする人に届けます。","wrapGroups":["必要とする人に届けます。"],"wrapBreaksAfter":["今知っておきたいことを、"]}
```

## 試験的な候補評価

現在はトップページのアプリ説明・活動の目的・ご案内カードの説明・お問い合わせ説明が対象です。別の範囲で試す場合は、その親に `data-wrap-evaluate` を付けます。見出しは対象にせず`balance`を維持します。

候補を段落全体で比較します。読点等→個別指定やグループ境界→文節境界を基本に、行末の余白・極端に短い最終行・意味グループ内の分割にペナルティを設けます。通常の文節による貪欲な折り返しと同じ行数の候補だけを比較します。

600文字超・180候補超・リンクやruby等を含む複雑な段落、領域より長い文節については評価せず、BudouX/CSSに戻します。候補評価は完全な意味理解・構文解析ではありません。自動で修飾関係を正確に判断することは保証できません。

実際のフォントと領域幅を測定し、`document.fonts.ready`後、フォント読み込み完了、ResizeObserverによる領域幅の変更で再計算します。幅変更の通知は120msでまとめ、文字・幅・フォントに変化がない段落の測定は再利用します。スクロールでは再計算しません。全サイトへの評価処理の拡大は、比較結果と負荷を見て段階的に行います。

## ビルド・プレビュー

Node.js 22以上とnpmを使用します。

```sh
npm ci --prefix website/tools
npm test --prefix website/tools
npm run build --prefix website/tools
node website/tools/verify-build.mjs
python -m http.server 8766 --directory _site
```

ブラウザで `http://localhost:8766/` を開きます。元ファイルの直開きではなく、公開と同じ `_site/` をプレビューしてください。生成先を自動削除せず上書きするため、ページや公開アセットを削除・改名した場合は、確認のうえ古い生成物を整理するか、新しい作業領域でビルドしてください。

GitHub Actionsでも固定依存関係を`npm ci`で取得し、同じビルドを実行します。`data/`は従来どおりバイト列を維持してコピーします。公式サイト専用ツールやnode_modulesは公開しません。

## 比較・検証

- `?jp-wrap=css`：従来のCSS。自動候補と意味グループの制約を無効化。
- `?jp-wrap=budoux`：BudouXと意味グループ、候補評価なし。
- `?jp-wrap=evaluate`：通常表示。トップページの試験対象で評価処理あり。
- DevToolsの`window.MiraiTypography.stats`で処理数・処理時間（累計）を確認できます。

```sh
cd website/tools
npx playwright install firefox webkit
cd ../..
node website/tools/qa.mjs
```

QAはWindowsのEdge、Playwright版Firefox・WebKitを使用します。WebKitはSafari実機の代替にはなりません。出力先は`QA_DIR`環境変数で指定でき、省略時は`website/tools/reports/`です。

コピーした文章・ブラウザ内検索・読み上げ順・リンクや太字の保持、極端な空白、改行行数、狭い幅、JS無効時も確認してください。画面幅ごとに同じ改行位置を保証するものではありません。

## 問題がある場合

- 一箇所だけ除外：親または対象に `data-wrap="off"` を指定。
- 比較・緊急確認：URLに`?jp-wrap=off`を付けて従来のCSSに戻す。
- 評価処理だけ止める：`website/tools/browser.mjs`の通常モードを`budoux`へ変更して再ビルド・公開。
- 全体を恒久的に従来表示へ戻す：`website/tools/browser.mjs`の通常モードを`off`に変更して再ビルド・公開。ライブラリや生成物を先に削除しないこと。
- JSが無効・実行に失敗した場合も、静的な本文とBudouX候補で読めます。測定処理の例外は通常候補の表示に戻します。

BudouXとモデルはApache-2.0、固定版のライセンス・NOTICEを`assets/licenses/budoux/`に同梱しています。CDN・外部解析APIへ文章を送ることはありません。依存更新時はlockfileとライセンスを確認し、比較テストを再実施してください。


## 今回の採用判断（2026-11-28）

BudouXは全9ページ337ブロック、お知らせは生成後にも適用。候補評価はトップページの主要説明文16ブロックに限定採用しました。PC幅1366pxでは、指定4例の末尾を意味グループごとに次行へ送ることをEdge・Firefox・WebKitで確認できました。

同一端末での比較では、全本文を評価したプロジェクト紹介ページは1回約43〜94ms、通常の候補生成・表示のみは約1〜5msでした。主要説明文だけのトップページは1回約12〜35ms。段落全体のDOM測定は長文ページや低速端末で負担になるため、全面適用は見送りました。`?jp-wrap=evaluate-all`は比較・負荷測定専用で、通常の公開表示には使用しません。

追加スクリプトは約43KB（gzip約16KB）。実測時間は端末・キャッシュ・フォントによって変わります。WebKit検証はSafari実機検証を代替しません。

新しいページを追加する場合は既存ページの共通CSS/スクリプト参照を踏襲し、新しいトップレベルの公開ディレクトリは`website/tools/build.mjs`のコピー対象にも追加します。追加ディレクトリ内のHTMLは同じ処理を自動的に受けます。

評価済み区間では`overflow-wrap: normal`を使い、任意位置での緊急分割を抑えます。実際の描画ではみ出し・文節内の分割が検出された場合は、その段落だけ評価を解除して通常のBudouX/CSS表示へ戻します。幅の再測定時は以前の評価状態を一時解除し、広い画面での最小幅が狭い画面へ持ち越されないようにしています。

共通CSS・JavaScriptの実装を変更した場合は、HTML内の対応する参照の`v`も更新してキャッシュを更新してください。通常の文章変更では不要です。

評価範囲のブロックには`contain: inline-size`を用い、評価した語句が親Gridの最小幅を押し広げないようにしています。この機能に非対応の場合は評価処理を行わず、通常のBudouX/CSS表示を維持します。

要素自身のサイズでは判定できない描画差もあるため、評価後にページ全体の横はみ出しを検査します。検出時はその表示幅で追加評価を休止し、通常のBudouXへ戻します。別の幅へ変わると再試行します。WebKitの一部の狭い幅ではこのフォールバックが動作します。
